# PRD — نظام محاسبي متكامل عربي

## أصل الطلب
بناء نظام محاسبي عربي كامل يعمل محلياً على Windows، مع فصل كامل بين جهتين: «النقابة العامة» و«مشروع التكافل الاجتماعي»، ويشمل الودائع البنكية، التسويات، الإيرادات، المصروفات، دفتر الأستاذ، القيود اليومية، شجرة الحسابات، ميزان المراجعة، الأصول الثابتة، العهد والسلف، عضوية مشروع التكافل، استيراد بيانات العضوية مع مراجعة قبل الاعتماد، تقارير العضوية، الفاتورة الإلكترونية الداخلية، سجل التدقيق، النسخ الاحتياطي، وإصدار setup.exe عبر NSIS.

## المستخدمون المستهدفون
- أدمن الجهة: يضبط المستخدمين، الخواص، نسب إهلاك الأصول، الحسابات، الفترات، النسخ الاحتياطي، والتقارير.
- مستخدم إدخال البيانات: يسجل الإيرادات والمصروفات والودائع والأصول والعهد والسلف والعضويات ويستورد ملفات العضوية حسب صلاحياته.
- مستخدم المراجعة/العرض: يراجع التقارير والقيود وميزان المراجعة والأصول والعضويات والتقارير السنوية.

## المتطلبات الأساسية
- واجهة عربية RTL بالكامل.
- عزل كامل للبيانات حسب `organization_id`.
- مشروع التكافل له صفحة رئيسية بقسمين: الحسابات والعضوية.
- جميع APIs تحت `/api`.
- MongoDB فقط عبر `MONGO_URL` و`DB_NAME`.
- توليد قيود يومية تلقائية متوازنة للعمليات المالية.
- ربط القيود بشجرة الحسابات وظهورها في ميزان المراجعة.
- استيراد بيانات العضوية من الملفات مع شاشة مراجعة قبل الاعتماد وتجاهل أي بيانات زائدة غير معتمدة.
- إصدار Windows installer محدث بعد كل تغيير جوهري.

## المعمارية الحالية
- Frontend: React + Tailwind + shadcn/ui، صفحات منفصلة لكل وحدة.
- Backend: FastAPI monolithic في `/app/backend/server.py`، مع Motor/MongoDB وPydantic response models.
- Accounting engine: دوال داخل backend لتوليد قيود يومية تلقائية وربط الحسابات عبر `system_key`.
- Fixed assets engine: قوائم أصول قابلة للإضافة/الحذف، نسب إهلاك قابلة للتعديل من الأدمن، حساب إهلاك شهري، وتاريخ تكهين تلقائي.
- Custody/advances engine: صرف عهد وسلف وتسويتها بقيود يومية تلقائية متوازنة.
- Membership engine: حساب سن/تاريخ المعاش تلقائياً، استيراد العضويات على مرحلتين preview/commit، والتقارير السنوية لمشروع التكافل فقط.
- Packaging: NSIS config في `/app/local_install/BankDepositSystem.nsi` يقرأ من `/app/release/BankDepositSystem`.

## ما تم تنفيذه حتى 2026-04-30
- عزل الجهتين وتسجيل دخول منفصل لكل جهة.
- إعدادات الخواص لكل جهة من لوحة الأدمن.
- الودائع البنكية، التسويات، الإيرادات، المصروفات، المصروفات البنكية، تحليل المصروفات، دفتر الأستاذ.
- القيود اليومية اليدوية والتلقائية مع ترقيم مستقل لكل جهة.
- شجرة الحسابات التلقائية وربط القيود بها.
- ميزان المراجعة من القيود المعتمدة.
- الفاتورة الإلكترونية الداخلية، سجل التدقيق، إقفال الفترات، الاعتمادات، والنسخ الاحتياطي.
- وحدة الأصول الثابتة: تسجيل أصل، إضافة/حذف أسماء أصول من القائمة، نسب إهلاك قابلة للتعديل من الأدمن، تاريخ شراء YYYY-MM-DD، تاريخ تكهين تلقائي، تقارير أصول وإهلاك، قيود شراء وإهلاك تلقائية.
- وحدة العهد والسلف: تسجيل عهدة/سلفة، تسوية تلقائية كمصروف أو رد للبنك، قيود تلقائية متوازنة، تقرير وطباعة.
- تقسيم مشروع التكافل إلى «الحسابات» و«العضوية».
- وحدة العضوية: تسجيل عضو، بحث بالاسم وتقرير عضو، تصفية خروج معاش، وحجم العضوية الحالي.
- استيراد العضوية من PDF نصي/DOCX/XLSX/CSV مع شاشة مراجعة قبل الاعتماد وربط تلقائي للحقول المطلوبة فقط.
- التقرير السنوي للعضوية حسب المحافظة واللجنة.
- ملف التثبيت الحالي: `/app/dist/BankDepositSystemSetup.exe` متاح عبر `/api/download/setup`.

## وحدة الأصول الثابتة — تفاصيل التنفيذ
- التصنيفات: الأثاث كود 5، آلات مكتبية كود 101، الخزائن كود 151، الأجهزة الكهربائية كود 155.
- نسب الإهلاك قابلة للتعديل من صفحة الأدمن لكل جهة، وتطبق على الأصول الجديدة.
- يمكن اختيار أصل من القائمة أو إضافة أصل جديد وحفظه في القائمة، ويمكن حذف عنصر من القائمة.
- تاريخ الشراء يظهر ويدخل بصيغة YYYY-MM-DD.
- تاريخ التكهين يحسب تلقائياً = تاريخ نهاية آخر شهر يصل فيه مجمع الإهلاك إلى تكلفة الأصل.
- تقارير الأصول تدعم فلترة حسب التصنيف والأصل، وطباعة الأصول المسجلة.
- تقرير إهلاك الفترة يدعم سنوي فقط أو سنوي/شهري مع طباعة.

## وحدة العهد والسلف — تفاصيل التنفيذ
- صفحة `/custody-advances` ضمن الحسابات.
- صرف عهدة/سلفة ينشئ قيداً تلقائياً: مدين العهد والسلف، دائن البنك.
- التسوية كمصروف تنشئ قيداً تلقائياً: مدين تسوية العهد والسلف، دائن العهد والسلف.
- التسوية كرد للبنك تنشئ قيداً تلقائياً: مدين البنك، دائن العهد والسلف.
- الحذف للأدمن يحذف السجل والقيود التلقائية المرتبطة.

## وحدة العضوية — تفاصيل التنفيذ
- صفحة العضوية متاحة لمشروع التكافل الاجتماعي فقط.
- بيانات العضو: محافظة، اللجنة النقابية، رقم العضوية، الاسم، الرقم القومي، تاريخ الميلاد، العنوان، ومستلم إعانة الوفاة.
- يمنع تكرار رقم العضوية والرقم القومي داخل الجهة، ويجب أن يكون الرقم القومي 14 رقم.
- البحث بالاسم يعرض صفوف النتائج، وزر عرض يفتح تقريراً منظماً مع طباعة وخروج.
- تصفية خروج المعاش تعتمد على المحافظة/اللجنة والسنة/الشهر فقط، وتعرض مربع عدد الأعضاء خروج معاش.
- حجم العضوية الحالي = إجمالي الأعضاء المسجلين - من خرجوا على المعاش حتى التاريخ الحالي.
