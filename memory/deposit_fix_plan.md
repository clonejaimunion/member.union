# بنود التنفيذ (على حساب آخر لاحقاً)

## أ. تنظيف البيانات (سكربت migration لمرة واحدة، قراءة ثم كتابة محكومة)
1. حذف قيود journal_entries حيث source_type="revenue" والإيراد المصدر (revenues.collection_method)="deposit_maturity"،
   + حذف/تعطيل سجلات revenues نفسها بطريقة deposit_maturity (وإلا الكود يعيد توليد القيد). (6,350,000)
2. إزالة تكرار deposit_maturity_principal: لكل source_id يحتفظ بأقدم قيد ويحذف الباقي. (حذف 9 قيود زائدة)
3. إزالة قيود expense deposit_link المزدوجة: حذف قيد المصروف المطابق لقيد deposit، مع مراجعة سجل المصروف
   (expenses.expense_category="deposit_link") لمنعه من توليد قيد وديعة. (2,050,000)
4. بعد كل خطوة: التحقق من رصيد البنك وحساب ودائع لأجل مقابل الأرقام المرجعية.

## ب. إصلاح المصدر البرمجي (server.py)
5. **منع «استحقاق وديعة» من تسجيل إيراد**:
   - REVENUE_RULE_ACCOUNT_MAP["deposit_maturity"] (~سطر 3539) + journal_for_revenue (~3687) + REVENUE_DIRECT_BANK_METHODS (~3536).
   - القرار: إزالة deposit_maturity من مسار الإيرادات تماماً، وإدارة الاستحقاق عبر آلية الفك (بند 7).
6. **منع ExpenseEvent/deposit_link من إنشاء قيد وديعة**:
   - journal_for_expense (معالجة expense_category="deposit_link") + EXPENSE_RULE_ACCOUNT_MAP.
   - ربط الوديعة يُدار حصراً عبر DepositEvent (journal_for_deposit_principal ~3657).
7. **بناء آلية فك الوديعة الصحيحة عند الاستحقاق** (دالة جديدة journal_for_deposit_maturity):
   - عند الاستحقاق: مدين البنك (الأصل) / دائن ودائع لأجل (الأصل) — مرة واحدة فقط (idempotent حسب source_id).
   - الفائدة المكتسبة تُسجّل منفصلة: مدين البنك / دائن «إيرادات فوائد ودائع» بقيمة الفائدة الفعلية فقط (من calculate_deposit_interest_for_period).
8. **ضبط التجديد/إعادة الربط**:
   - POST /banks/{bank_id}/deposits (~7616) + auto_renew_due_deposits (~7694) + PUT (~7741).
   - عند التجديد: فكّ القديمة (قيد فك) + ربط الجديدة (قيد ربط)، بدون إيراد وبدون ExpenseEvent.

## ج. إعادة الحساب والتحقق النهائي
9. إعادة بناء القيود المتأثرة والتحقق من كل الأرقام المرجعية أعلاه + is_accounting_valid=True.
10. حسم الفائدة المعروضة (781,480.52) مقابل المرجع مع المستخدم قبل الإقفال.
